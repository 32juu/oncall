# SuperBizAgent 项目宪法

## 核心原则

### I. 需求即用户价值（WHAT/WHY，技术无关）
每个 spec 只描述系统对外提供什么、用户获得什么价值；严禁混入技术实现、框架、API 或流程细节。用户故事 + 可度量验收，读者是业务干系人（含面试/复盘语境）。

### II. 特性切片可独立交付（NON-NEGOTIABLE）
一次 `/speckit-specify` 只产出一个 feature spec；spec 内每个 User Story 必须能独立实现、独立测试、独立演示成可用 MVP。工程/流程目标（六件套落地、CI/CD、重写 CLAUDE.md 等）不进 spec，保留在 `SuperBizAgent_Claude优化执行文档.md`。

### III. 测试必带（NON-NEGOTIABLE）
无测试 = 缺陷。新增/改动代码必须携带可运行测试；关键路径至少冒烟覆盖（supervisor 循环、认领状态机、报告模板）。`mvn verify` 通过是提交前提。

### IV. 新增工具三件套
任何新增 `@Tool`：注册 + 权限校验 + 单元测试，缺一不可；工具结果需截断防上下文爆炸；高危（写操作）工具默认拒绝并审计。

### V. mock 只用于测试
真实数据源不可用时的 mock 必须有开关并注明，禁止 mock 冒充生产路径。真实路径优先经 MCP/外部数据源（如腾讯 CLS），不在 Java 里留半真实现。

## 工程硬约束（违反视为阻塞）

- 会话/状态禁止放内存（ConcurrentHashMap 滑动窗口），一律持久化，重启不丢。
- 向量维度固定 1024；换 embedding 模型必须先重建 Milvus 集合 `biz`。
- 文档检索路径 `_source` 统一正斜杠。
- AIOps 诊断报告模板固定；planner 的 FINISH 输出必须纯 Markdown 非 JSON。
- 依赖版本锁定；`StreamingOutput` 等框架枚举改动前核对框架版本。

## 范围纪律（当前边界 / 后续切片）

以下内容不属于本仓库任何已交付 spec，属后续切片：自动修复/自愈执行（高危工具片）、真实监控/日志数据源接入（基础设施片，走 MCP）、账号登录与 RBAC 权限体系（权限片）、AIOps 诊断引擎本身重写、复盘报告导出。

首个切片「告警认领与处置」聚焦责任闭环：认领 → 归属 → 防重复接管 → 持久化；抑制窗口与处置记录同 spec 内降为 P2/P3；**不做改派/移交**。

## 治理

宪法优先于其他实践；新增/修订需文档化并经用户确认。`specs/` 产物、执行文档、CLAUDE.md 冲突时，以本宪法 + CLAUDE.md 为准，冲突须显式记录。
